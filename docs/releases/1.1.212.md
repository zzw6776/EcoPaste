# 1.1.212

- 文本、图片和文件的记录默认同步到已启用通道，图片和文件先同步记录、再独立传输内容；自动大小上限和通道选择只影响内容传输，接收端继续遵守自己的自动下载配置。
- 修复手动上传和重试被自动大小上限降回“仅同步记录”的问题；超出自动上传上限的文件不会自动上传，点击上传可补充完整内容，排队期间不会重复提交任务。
- 局域网图标以最新复制及接收端回执为准：仅记录到达显示蓝色，完整内容确认后显示绿色；修复重复复制继承旧绿色、离线设备导致一直等待，以及等待回执时重复发送的问题。
- 云端图标以 Hub 实际保存的内容为准，修复把本地已有文件误判为云端完整可用的问题；相同内容沿用已确认的云端状态，完整可用后显示绿色，积压状态追平时减少反复闪烁。云端已有相同文件时，传输列表显示“文件已存在，无需上传”，不再计入虚假的上传量。
- macOS、Windows 和 Android 收到完整文件或另存到所选位置后，可以手动上传云端；普通文件直接从保存位置流式加密上传，无需复制回内部缓存或生成完整临时密文。修复部分 Android 文件提供器暂时报错大小，导致刚保存的文件被误判为不存在的问题。
- Android 分享文件在本地导入完成、正式入队时重新判断可用通道；大文件有已连接的局域网设备时仅走局域网，否则走云端，记录仍同步到已启用通道。导入结束后收起导入进度，实际传输时再显示上传进度。
- 单条卡片同步失败不再中断其它卡片或关闭健康的局域网连接；准备失败会显示原因并提供重试入口，重试重新准备当前内容，取消或失败不会删除已同步的记录。
- 传输列表明显区分“进行中”和“最近记录”，进行中任务置顶；已结束记录保留 24 小时、最多 50 条，并提供清空入口，每条记录的大小与任务开始时间在同一行显示。
- 升级会重建旧版本不准确的同步状态，通过实际内容可用性和接收回执恢复显示，保留历史记录与文件；Mac 与 Android 需一起更新。
- 调整前端公共依赖分包，减小页面入口脚本体积。
