# 1.1.177

- 本地容量检查默认在剪贴板变化后最多每 10 分钟执行一次，并每 60 分钟兜底检查；两个间隔均可在偏好设置中调整。
- 本地与云端容量清理统一采用可配置的迟滞策略，默认占用率超过 90% 时触发并清理到 70%；本地清理继续保留收藏、置顶及尚未完成的明确传输，并按最近使用时间优先淘汰最旧普通记录。
- 偏好设置侧栏的存储状态颜色会跟随当前清理触发占比和目标占比，不再使用固定阈值。
- 新增远端文件自动下载上限；局域网会在传输文件字节前先判断该上限，超过阈值时仅同步文件名、大小等信息，手动下载会先选择系统保存位置，不占用 EcoPaste 托管缓存。
- 客户端不再长期保留同步文件的密文副本；普通文件会边读取、边加密、边上传，不再先生成一份完整临时密文，目录归档仅在实际传输期间临时生成并及时回收，升级后会直接删除旧版 `sync-blobs` 目录。
- 文件通过局域网或云端传输时会显示进度、速度、耗时和预计剩余时间，并支持取消与失败重试；下载路线不可达或缺少文件时会在同一任务内尝试另一条可用路线，多文件下载失败或取消后不会留下不完整文件，桌面端替换已有文件时也会恢复原文件，Android 会在所选目录内以临时文件安全提交。
- 文件准备阶段现在作为单一全局任务安全取消，事件生成后再按云端或局域网拆分传输；排队阶段取消后不会被当前传输批次重新创建上传任务，取消完成前也不会发布终态或误删随后重试的任务，目录归档和临时加密会及时停止并回收，传输历史不再持续占用内存。
- 已有同内容文件的本地路径失效时会恢复为可下载状态或改用新落地的托管文件；切换同步空间或所有可用路线都确认文件已被回收后，远端文件卡片会保留并明确显示为已失效。
- Android 分享上传会在已有局域网设备连接时仅走局域网，否则走云端；上传过程中不会静默切换路线。
- Hub 取消固定的单文件大小上限，改为写入前检查实际磁盘可用空间；同步空间容量作为软预算，超过触发线后在后台按当前最严格的清理目标回收旧数据，不因单个大文件直接拒绝上传。
- 修复 Android 大目录保存超时或目标初始化失败后可能继续写入已删除临时目录，以及 Hub 密文文件缺失时远端卡片无法正确标记失效的问题。
- 修复明确发起的文件传输在离线或失败期间被本地容量清理提前回收，以及 Hub 异常退出或文件删除失败后残留密文无法再次清理的问题。
- 备份恢复现在只导入真实本地历史和资源，不再带入旧设备或旧同步空间的传输队列、加密事件及未下载远端文件卡片；合并与覆盖恢复采用一致的数据边界。
- 修复英文界面在文件上传准备或取消失败时显示中文错误的问题。
- 局域网同步需要两端客户端都升级到 1.1.177；云端大文件、容量回收及缺失文件状态收敛需要 Hub 0.1.27。
