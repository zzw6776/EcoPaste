# Android 主界面分类分页手势设计

> 状态：方案已于 1.1.90 实现，1.1.91 根据真机反馈改为在视口捕获阶段主动启动 Motion 手势，自动检查已通过，仍待 Android arm64 release 真机验收。本文记录 1.1.87 与 1.1.88 真机反馈后的根因判断、实现方向、验证方法和回退边界；在完成本文真机验收前，不宣称主界面左右滑动已经修复。

## 问题描述

Android 主界面按“全部、收藏、文本、图片、文件”切换剪贴板分类。目标交互是分页内容跟随手指连续移动：拖到一半时，视口中应同时显示当前页和相邻页，松手后根据拖动意图切换或回弹。

现有实现没有达到这个目标：

- 1.1.87 使用浏览器原生横向滚动与 `scroll-snap`，真机反馈与改动前没有可感知差异。
- 1.1.88 改为 React Pointer Event 驱动 `translate3d`，真机反馈进一步退化为没有滑动效果。
- 1.1.90 已删除 1.1.88 的手写 Pointer 状态机并替换为 Motion 受控分页，不再在旧实现上叠加阈值或事件补丁。

目前没有连接可读取日志的 Android 设备，无法证明 1.1.88 的事件具体中断在 `pointermove`、指针捕获还是 WebView 与虚拟列表的手势竞争。本文只把真机可复现结果和代码中能够确认的结构性问题作为结论，不猜测某一个浏览器事件必然是唯一故障点。

## 实现前链路

主界面仍是一个 Tauri Android WebView，不是原生 Android 列表：

```text
Rust 查询命令
    |
    v
useClipboardItems
    |
    v
List + react-virtuoso
    |
    v
ClipboardCard

clipboardViewState
    |----------------------|
    v                      v
Header 分类选中态       当前 List 的查询条件
```

`src/pages/Clipboard/index.tsx` 同时负责 Bottom Sheet、分类状态与横向分页；`src/pages/Clipboard/components/List.tsx` 内部是可纵向滚动的 `react-virtuoso`；卡片还包含点击粘贴、按钮操作和浏览器拖拽行为。

因此主界面手势不是单纯的横向轮播。它需要在同一触摸序列中协调：

- 横向分页跟手。
- `Virtuoso` 的纵向滚动。
- 卡片的点击粘贴，滑动不能误触发粘贴。
- 卡片内部按钮和可预览内容的操作。
- 相邻分类数据提前渲染，不能在松手后才替换内容。

## 根因判断

### 1. 交互模型与实现方式不匹配

1.1.88 自行维护方向锁、指针捕获、位移、速度、边缘阻尼和吸附动画。横向手势直到越过方向阈值后才调用 `setPointerCapture`，而事件起点通常位于 `Virtuoso` 的滚动节点或复杂卡片内部。在 Android WebView 中，只要事件在进入横向状态前被滚动容器、浏览器拖拽或系统手势接管，父级 React 处理器就无法继续完成状态机。

继续调整距离、速度或 CSS 只能改变已经收到完整事件时的行为，无法修复事件序列本身不完整的问题。

### 2. “切换筛选条件”不等于“分页”

无缝横向分页要求当前页和相邻页在拖动期间同时存在于同一条轨道。只更新一个 `List` 的筛选条件，无论查询多快，都只能在切换后替换内容，无法出现“一半当前页、一半相邻页”。

反过来，长期挂载全部五个完整 `List` 会让每一页都持有虚拟列表、查询和事件订阅，增加首屏工作量，也会放大状态同步问题。需要只预装完成连续手势所必需的页面。

### 3. 卡片交互会参与手势竞争

移动端如果在按下阶段执行主要动作，或保留 HTML 原生 `draggable`，一次横向拖动可能先触发粘贴，也可能被浏览器拖拽接管。分页容器修好后，卡片仍必须遵守“完整点击才执行、拖动不执行”的契约。

## 不采用的方案

### 继续修补手写 Pointer 状态机

该方向需要自行覆盖窗口级事件监听、丢失捕获、触摸取消、方向锁、速度采样、滚动补偿、边缘约束和动画中断。它重复实现成熟手势库已有能力，而且 1.1.88 已经证明只补父级 Pointer 处理器不能稳定工作。

### 继续调整 `scroll-snap`

原生滚动适合浏览器主导的滚动容器，但当前页面嵌套了纵向虚拟列表和卡片交互，且 1.1.87 真机没有达到跟手分页效果。在没有新的设备证据前，不再通过修改 `touch-action`、`overflow` 或吸附参数重复尝试同一路径。

### Android 原生 `ViewPager2`

主界面内容、查询状态和卡片交互都在单个 Tauri WebView 内。使用 `ViewPager2` 要么把五页改写为原生 Android UI，要么维护多个 WebView 并同步 Rust 数据、前端状态、主题和交互。它会把一个局部手势问题扩大成跨层重构，不符合当前最小改动原则。

### 同时常驻全部分类列表

五个 `Virtuoso` 同时挂载会增加查询、订阅、测量和内存压力。无缝视觉只要求当前页及相邻页存在，不要求所有页面永久活跃。

## 推荐方案

使用项目已经依赖的 Motion 12 实现受控横向分页，删除 1.1.88 的手写 Pointer 状态机。Motion 负责指针生命周期、窗口级移动监听、方向处理、速度信息和动画；业务代码只决定目标页并同步分类状态。

### 页面结构

```text
MobileCategoryPager viewport（overflow hidden）
    |
    v
motion.div track（drag="x"）
    |----------------------|----------------------|
    v                      v                      v
上一页 List             当前页 List             下一页 List
inactive                active                  inactive
```

轨道的 `x` 是唯一视觉位置来源。视口宽度变化时重新计算各页位置；分类标签点击、外部状态变化和拖动结束都通过同一套吸附函数移动轨道，不能再分别维护 DOM `style.transform` 与 React 分类状态。

### 手势职责

- 轨道使用 `motion.div drag="x"`，只允许横向拖动。
- 使用 `useMotionValue` 保存连续位移，并通过 Motion 的动画能力吸附到目标页。
- 关闭自由惯性，业务上一次手势最多切换一个相邻分类，避免快速甩动跨过多个分类。
- 左右边界使用约束与轻量弹性，边缘可以有阻力，但不能露出空白页。
- `onDragEnd` 只读取 Motion 提供的 `offset.x` 与 `velocity.x`，通过一个纯函数决定“回弹、上一页、下一页”。
- 距离和速度阈值集中为具名常量，并在真机录屏与测试数据基础上确定；在取得设备数据前，本文不把任意数值定义为正确阈值。
- 拖动过程中只更新 Motion 位移，不持续写 `clipboardViewState`，避免每帧触发分类查询和 Header 重渲染。

Motion 在 `drag="x"` 下会为元素应用适合保留纵向滚动的触摸行为，并在手势会话中使用窗口级指针监听。选用它的原因是直接替代当前失败状态机的职责，不是为了增加视觉特效。

### 页面与数据生命周期

页面以五个内置筛选的稳定索引为基准。任一时刻只挂载：

- 当前页。
- 存在时的前一页。
- 存在时的后一页。

相邻页在进入手势前立即开始自己的首批查询，因此拖动时展示的是相邻页真实内容，而不是松手后替换当前页。远离当前页的列表卸载，避免五个虚拟列表长期订阅相同的全局事件。

`List` 需要显式区分 `active` 与预载状态：

- `active=true` 的当前页可以响应键盘导航、原生菜单、统计更新和当前选中项。
- `active=false` 的相邻页只负责查询与渲染，不响应只属于当前页的全局交互。
- 剪贴板数据库更新后，已挂载的相邻页应刷新；重新挂载的页面按现有查询链路取得最新数据，不建立前端业务数据副本。

若相邻页的真实查询尚未完成，只能显示现有列表加载态；不得先复制当前页内容制造“无缝”假象。需要通过真机验证查询是否能在用户开始拖动前完成，并根据证据决定是否扩大预取范围。

### 状态提交顺序

一次拖动遵循以下顺序：

1. 按下并移动时，仅轨道跟手，当前分类状态不变。
2. 松手后，目标决策函数返回当前页或相邻页。
3. 轨道开始吸附到目标页。
4. 确认目标后只提交一次分类状态，使 Header 与查询条件指向同一索引。
5. 页面集合围绕新索引更新为“前一页、当前页、后一页”。

分类标签点击和其他外部分类变化也进入同一流程。不能让 Header 已经切到新分类而轨道仍停在旧页，也不能在拖动途中反复修改全局筛选导致页面内容跳变。

现有自定义分组不新增横向页。选中自定义分组时保留当前产品语义；用户通过横向分页进入内置分类后，再按目标页一次性清除自定义分组条件。实现前需要用当前代码路径补充自动测试，确保该切换不会产生短暂的错误查询组合。

### 卡片交互契约

- Android 卡片主要动作只在完整 `click` 后执行，不能在 `pointerdown` 或 `mousedown` 时粘贴。
- 移动端关闭卡片的 HTML 原生拖拽，避免与横向分页竞争。
- 横向位移达到手势判定后，该序列不得再触发卡片点击。
- 卡片按钮继续阻止事件冒泡，只执行按钮自身操作。
- 纵向滑动继续交给 `Virtuoso`，不能因横向分页而出现明显卡顿或误切页。

## 预计改动范围

- `src/pages/Clipboard/index.tsx`
  - 删除 1.1.88 的 Pointer 状态机与直接 DOM transform 写入。
  - 保留 Bottom Sheet 和分类状态组合职责。
- `src/pages/Clipboard/components/MobileCategoryPager.tsx`
  - 新增聚焦的移动端分页组件，封装 Motion 轨道、尺寸测量、边界和吸附。
  - 组件只接收当前索引、页面描述与索引变更回调，不持有剪贴板业务数据副本。
- `src/pages/Clipboard/components/List.tsx`
  - 支持当前页与相邻预载页的明确视图参数。
  - 非当前页关闭只属于活动列表的全局交互。
- `src/pages/Clipboard/components/cards/ClipboardCard.tsx`
  - 保证移动端点击与浏览器拖拽不抢占横向手势。

最终实现应以实际调用关系为准保持最小改动。若 `MobileCategoryPager` 无法形成清晰的单一职责，可以留在现有组件中，但不得恢复分散的 DOM 引用和手写事件状态机。

## 验证计划

### 自动验证

- 目标页纯函数覆盖短距离回弹、距离切换、快速甩动、反向速度和首尾边界。
- 一次手势最多移动一页，首尾页不会产生越界索引。
- 外部分类变更与拖动结束使用同一目标位置计算。
- 相邻页只预载数据，不响应活动页专属事件。
- 横向拖动后不执行卡片主要动作，普通点按仍执行一次。
- 运行前端 lint、类型检查和必要的单元测试。

### Android arm64 release 真机验证

按项目规则由 Android arm64 release 构建进行最终验收，至少覆盖：

- 从卡片正文、图片、空白区域和列表不同纵向位置开始慢速横拖，页面全程跟手。
- 拖到约一半时，同时看到当前页和相邻页的真实内容，没有松手后才替换的闪动。
- 未达到切换意图时平滑回弹；达到切换意图或快速甩动时只进入相邻一页。
- 第一页向右和最后一页向左只有阻力反馈，不出现白屏或错误分类。
- 横向滑动不粘贴、不打开预览、不触发卡片按钮；普通点击行为保持不变。
- 纵向快速滚动、惯性滚动和滚动中轻微横向偏移不会误切分类。
- 连续左右切换、动画未结束时反向拖动、旋转或视口尺寸变化后位置仍正确。
- 点击 Header 分类后使用同一吸附动画，选中态、页面内容与查询条件一致。
- 相邻页首次加载与剪贴板更新期间无旧分类内容冒充新分类。

真机仍失败时，应先采集 WebView 指针事件、Motion 回调和帧表现证据，再决定下一步。不得同时保留 Motion、原生滚动和手写 Pointer 三套互相兜底的手势实现。

## 回退边界

如果 Motion 方案在真机上无法满足纵横手势协调，回退应恢复到“分类标签可点击、横向分页暂时关闭”的单一路径，保证功能可用，再根据日志重新设计。不能回退到 1.1.87 或 1.1.88 后继续叠加补丁。

Android 上滑弹窗边缘误收回是独立的原生输入监控问题，不纳入本分页重构。两项修复可以在同一版本验收，但代码职责和回退必须分开。

## 完成标准

只有 Android arm64 release 真机同时满足“页面跟手、半页并显、松手吸附、纵向滚动正常、滑动不误触卡片、分类状态一致”，才能认为主界面左右滑动已修复。仅看到分类最终切换、仅桌面浏览器模拟正常，或只通过编译检查，都不满足本文目标。
